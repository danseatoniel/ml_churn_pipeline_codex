# ml-churn-feature-pipeline

A compact, local-first Python repository for testing repo triage agents against a realistic machine learning data pipeline.

The project ingests a raw customer churn CSV, validates the contract, cleans common tabular data issues, creates model-ready churn features, and writes a processed CSV. It is intentionally small, deterministic, and dependency-light so future test failures are easy for a triage agent to diagnose and fix.

## Setup

```bash
uv sync --no-editable
```

## Run Tests

```bash
uv run --no-editable pytest
```

## Run The Pipeline

```bash
uv run --no-editable python -m churn_pipeline.cli run \
  --input data/sample/raw_customers.csv \
  --output data/processed/features.csv
```

The installed entry point is also available after `uv sync`:

```bash
uv run --no-editable churn-pipeline run \
  --input data/sample/raw_customers.csv \
  --output data/processed/features.csv
```

For reproducible feature snapshots, pass an explicit reference date:

```bash
uv run --no-editable churn-pipeline run \
  --input data/sample/raw_customers.csv \
  --output data/processed/features.csv \
  --reference-date 2024-04-01
```

## Data Contract

Expected raw columns:

- `customer_id`
- `signup_date`
- `last_login_date`
- `country`
- `age`
- `plan_type`
- `monthly_spend`
- `num_support_tickets`
- `is_active`
- `churned`

See [docs/data_contract.md](docs/data_contract.md) for validation rules and missing-value handling.

## Repository Layout

```text
src/churn_pipeline/     Pipeline package
tests/                  Unit and integration tests
tests/fixtures/         Small CSV fixtures for deterministic tests
data/sample/            Example input data
docs/                   Data contract and future AWS deployment notes
```

The code does not require external services. It is structured so file IO can later be swapped for S3 and the CLI can be wrapped in Docker, AWS Batch, or ECS.
